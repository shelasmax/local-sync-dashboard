## Пульт управления переносами

Соберите регулярные переносы файлов в одном месте: создавайте профили хранилищ, проверяйте точный маршрут, делайте пробный запуск и следите за прогрессом, пока rclone копирует данные.

| Возможность | Что это даёт |
| --- | --- |
| **Профили хранилищ** | Повторно используйте локальные папки, смонтированные шары Synology, S3-совместимые хранилища и Яндекс Диск в разных задачах. |
| **Проверка до копирования** | Просматривайте пути источника и назначения, выбирайте подпапки и делайте dry-run перед переносом. |
| **Запуски вручную и по расписанию** | Запускайте по запросу, каждый час, день, неделю или по cron. Редактируйте и клонируйте задачи, приостанавливайте и возобновляйте расписания. |
| **Живой прогресс** | Отслеживайте байты и файлы, скорость, ETA, проверки и текущие объекты. |
| **Восстановление и диагностика** | Находите прерванные запуски и повторяющиеся ошибки, переходите к нужному сценарию встроенного Ops / Runbook. |
| **Настройки и история** | Задавайте лимит скорости, checksums, фильтры, `transfers`, `checkers` и `fast-list`; полная история хранится в отдельном архиве. |

> **Как работает копирование:** задачи используют [`rclone copy`](https://rclone.org/commands/rclone_copy/). Файлы, исчезнувшие из источника, автоматически не удаляются в назначении. Изменённые файлы по тому же пути назначения могут обновляться или перезаписываться; это не система версионных резервных копий.

## Поддерживаемые хранилища

| Хранилище | Как подключается |
| --- | --- |
| **S3 / S3-compatible** | Готовый rclone remote, bucket и необязательный prefix. |
| **Яндекс Диск** | Готовый rclone remote, например `yadisk:`. |
| **Synology** | SMB/NFS-папка, уже смонтированная на Mac в `/Volumes`. |
| **Локальные папки** | Любой доступный каталог на Mac. |
| **iCloud Drive / Google Drive for Desktop** | Локально доступные папки через профиль локальной папки. Прямой интеграции с облачными SDK нет. |

Все переносы идут **через ваш Mac**, включая cloud-to-cloud. Mac должен оставаться включённым, подключённым к сети и нужным томам. Приложение не монтирует сетевые папки и не создаёт rclone remotes автоматически.

## Быстрый старт

Потребуются **macOS**, **Python 3.11+**, **rclone** и **Git**. Установите rclone по [официальной инструкции](https://rclone.org/install/).

```bash
git clone https://github.com/shelasmax/local-sync-dashboard.git
cd local-sync-dashboard
python3 --version  # Нужна версия 3.11 или новее
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

Для облачных хранилищ сначала настройте подключения в rclone:

```bash
rclone config
rclone listremotes
```

Запустите панель:

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте **[127.0.0.1:8000](http://127.0.0.1:8000)**.

1. **Подготовка** (`/setup`): проверьте rclone, remotes и смонтированные папки.
2. **Профили** (`/profiles`): добавьте хранилища источника и назначения.
3. **Задачи** (`/jobs`): создайте задачу, проверьте маршрут и выполните dry-run.
4. **Запуски** (`/runs`): запустите копирование и следите за прогрессом.

Для Synology сначала подключите папку в Finder. Адрес вроде `smb://nas.local/media/photos` становится локальным путём, например `/Volumes/media/photos`. Указывайте фактический mount path, а не SMB URL или внутренний путь NAS вроде `/home`.

## Длительные переносы

- Запускайте приложение без `--reload`. Перезапуск прерывает переносы, которыми управляет приложение.
- Лимит по умолчанию — **6 часов на один запуск**. Перед длительным переносом измените его в **Ops / Runbook → лимит запуска** (`/ops`); интерфейс допускает 1–72 часа.
- После прерывания повторите тот же `copy`, чтобы докопировать дельту. rclone заново проверяет файлы; приложение не подключается к старому процессу и не гарантирует побайтовое продолжение файла.
- Оценивайте текущую попытку по живому прогрессу. Сводка предыдущего запуска описывает только ту попытку.

Для постоянной локальной эксплуатации есть [руководство по service-mode на macOS](docs/OPERATIONS.ru.md): service-копия, скрипты обновления и диагностики, резервное копирование и восстановление.

## Локальные данные и границы продукта

По умолчанию данные лежат в `var/`: SQLite — `var/app.db`, логи — `var/logs/`, снимки активных запусков — `var/runtime/`. Для другого каталога задайте `LOCAL_SYNC_DATA_DIR`.

Дополнительные секреты, введённые в приложении, хранятся в **macOS Keychain**. Авторизацией в облаках отдельно управляет **rclone**. Его конфигурацию и данные приложения следует хранить приватно.

Это локальная утилита для одного пользователя. Используйте адрес `127.0.0.1`: многопользовательской авторизации нет. Двусторонняя синхронизация, распространение удалений и разрешение конфликтов не поддерживаются. Очистка архива удаляет локальные записи и логи запусков, а не файлы источника или назначения.
