## English

**Timeouts & transfer progress**

See what actually arrived before a long-running copy reached its time limit.

### Highlights

- Timeout failures explicitly report the exceeded time limit instead of an early `0 B` progress snippet.
- Run details and timeout summaries show the files and bytes already transferred, together with the timeout window.
- The Ops / Runbook page now adjusts the default per-run timeout through existing app settings, without manual SQLite edits or a schema change.
- Documentation explains repeat-from-delta recovery and why live runtime snapshots are the best view of the current attempt.

### Operator note

Before a long copy, check the time limit in `/ops`. After a timeout, repeat the same route to copy the remaining delta; the app does not reattach to the old process.

## Русский

**Таймауты и прогресс переноса**

Теперь видно, сколько данных успело дойти до назначения до остановки длительного копирования.

### Что изменилось

- При таймауте сводка явно сообщает о лимите времени вместо раннего фрагмента прогресса с `0 B`.
- В деталях запуска и сводке таймаута видны уже перенесённые файлы и байты, а также лимит времени.
- На странице Ops / Runbook можно менять лимит одного запуска через существующие настройки приложения, без ручного редактирования SQLite и изменения схемы.
- Документация объясняет повторное копирование с дельты и роль живого runtime snapshot при оценке текущей попытки.

### Для эксплуатации

Перед длительным переносом проверьте лимит в `/ops`. После таймаута повторите тот же маршрут, чтобы докопировать дельту; приложение не подключается к старому процессу.
