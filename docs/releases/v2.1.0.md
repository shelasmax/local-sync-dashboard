## English

**rclone tuning per job**

Tune demanding routes directly in the job form.

### Highlights

- Added `transfers`, `checkers`, and `fast-list` to job forms, command previews, persistence, and actual `rclone copy` execution.
- An additive migration extends existing `sync_jobs` tables; startup and the job runner both guard the schema upgrade.
- Documented a small-file Synology → Yandex Disk tuning example using 8 transfers, 16 checkers, and fast-list. Results depend on the route and environment.
- Profile defaults with job overrides remain the next step; the controls in this release apply to individual jobs.

### Operator note

Back up local state with the app stopped before upgrading. Existing jobs retain default behavior until tuned; test concurrency and memory use on a small representative copy.

## Русский

**Настройки rclone для задач**

Настраивайте ресурсоёмкие маршруты прямо в форме задачи.

### Что изменилось

- Параметры `transfers`, `checkers` и `fast-list` добавлены в форму, preview команды, хранение и фактический запуск `rclone copy`.
- Additive-миграция расширяет существующую таблицу `sync_jobs`; обновление схемы проверяется при старте и со стороны job runner.
- Документирован пример настройки Synology → Яндекс Диск для мелких файлов: 8 transfers, 16 checkers и fast-list. Результат зависит от маршрута и окружения.
- Следующий шаг — настройки по умолчанию для профилей с переопределением в задаче; в этом релизе параметры задаются отдельно для каждой задачи.

### Для эксплуатации

Перед обновлением сохраните локальное состояние при остановленном приложении. Старые задачи используют прежнее поведение до настройки параметров; проверьте параллелизм и память на небольшой типичной копии.
