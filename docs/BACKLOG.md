# Backlog

## P0

### 1. Live progress для активных задач

Почему важно:
- сейчас run виден только после завершения
- пользователю не хватает ETA, скорости и процента выполнения

Что должно быть:
- progress bar
- ETA
- скорость
- передано / осталось
- обновление без перезагрузки страницы

### 2. Runtime state для long-running `rclone` jobs

Почему важно:
- сейчас активный перенос приходится мониторить внешним логом
- приложение не хранит live telemetry как first-class state

Что должно быть:
- таблица или in-memory state активных run
- периодическое чтение JSON stats из `rclone`
- API для текущего прогресса

### 3. Удаление задач из UI

Почему важно:
- профили уже можно удалять, задачи пока нет
- без удаления тяжело чистить конфигурацию

Что должно быть:
- delete action для `SyncJob`
- защита от удаления активной задачи
- корректное снятие расписания

## P1

### 4. Улучшенная диагностика профилей

Почему важно:
- статус `недоступен` полезен, но нужен richer контекст

Что должно быть:
- сохранение последней ошибки проверки
- кнопка “Проверить еще раз”
- отдельные hints для `S3`, `Yandex`, локальных папок

### 5. Dry-run и предпросмотр перед первым запуском

Почему важно:
- снижает риск перед переносом больших каталогов

Что должно быть:
- `rclone copy --dry-run`
- summary по количеству файлов и байт
- отдельный экран подтверждения

### 6. Конфигурирование `rclone remote` через UI

Почему важно:
- сейчас cloud setup разбит между UI и терминалом

Что должно быть:
- guided setup для `S3`
- guided OAuth flow для `Yandex Disk`
- безопасная работа с секретами и Keychain

## P2

### 7. Backup/restore конфигурации приложения

Почему важно:
- упростит перенос на другой Mac

Что должно быть:
- экспорт профилей и job без секретов
- импорт с валидацией

### 8. Нотификации о завершении и ошибках

Почему важно:
- long-running sync лучше не отслеживать вручную

Что должно быть:
- macOS notification
- опционально Telegram/email

### 9. Более богатая операционная документация

Почему важно:
- проект уже перешел из “прототипа” в “рабочий локальный инструмент”

Что должно быть:
- runbook по типовым ошибкам
- onboarding для новых remotes
- раздел recovery/rollback

## Отдельно вне MVP

- двусторонняя синхронизация
- delete propagation
- conflict resolution
- multi-user auth
- production-grade deployment за пределами локального Mac
