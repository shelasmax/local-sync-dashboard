# Backlog

## P0

### 1. Backup / restore конфигурации приложения без секретов

Почему важно:
- это верхний незакрытый приоритет в проекте
- упростит перенос на другой `Mac` и восстановление локальной установки

Что должно быть:
- экспорт профилей и задач без секретов
- импорт с валидацией и понятными ошибками
- явное описание, что секреты остаются в `macOS Keychain`
- ручная проверка профилей после restore

### 2. Связка диагностики профилей с `Ops / Runbook`

Почему важно:
- базовая диагностика уже есть, но следующий шаг не в количестве текста, а в качестве действия
- пользователь должен быстрее переходить от ошибки к следующему безопасному шагу

Что должно быть:
- более глубокие action-oriented подсказки по типам ошибок
- явные переходы из диагностики профиля в релевантные сценарии `/ops`
- более плотная связь между `последняя проверка`, `что проверить` и `что сделать дальше`

## P1

### 3. Операционный UX: нотификации, `launchd`, перенос на другой `Mac`

Почему важно:
- long-running sync неудобно отслеживать вручную
- проект уже используется как рабочий локальный инструмент, а не только как демо

Что должно быть:
- macOS notifications о завершении и ошибках
- более практичные `launchd`-сценарии и подсказки для локальной эксплуатации
- понятный flow переноса на другой `Mac`

### 4. Guided setup для `rclone remote` через UI

Почему важно:
- сейчас cloud setup всё ещё разбит между UI и терминалом
- это главный UX-разрыв для новых пользователей

Что должно быть:
- guided setup для `S3`
- guided OAuth flow для `Yandex Disk`
- безопасная работа с Keychain и секретами

## P2

### 5. Более богатый operational runbook

Почему важно:
- базовый `/ops` уже есть, но пока это ещё не полноценный рабочий операционный контур

Что должно быть:
- richer runbook по типовым ошибкам
- onboarding для новых remotes
- более явный recovery/rollback раздел
- короткие сценарии “что делать дальше” для основных инцидентов

### 6. Дополнительный content polish UI

Почему важно:
- базовый visual system уже стабилизирован
- теперь улучшения должны быть адресными, а не широкими

Что должно быть:
- точечная калибровка иконок, tooltip и контента в action-heavy экранах
- проверка, где icon-only controls достаточно понятны, а где нужен короткий текст
- дальнейшее выравнивание copy по `/profiles`, `/jobs`, `/runs`, `/ops`

## Уже сделано

- принято продуктовое решение: `re-attach` к живому `rclone` процессу не поддерживается
- `dry-run preview` для сохраненной задачи перед реальным запуском
- recovery flow для `interrupted` задач с повтором по дельте из `/runs`, `/jobs`, карточки конкретного запуска и главной
- явный manual-start экран `/jobs/{id}/start` с checklist и CTA перед длинным cloud запуском
- cloud-to-cloud предупреждения в `/setup`, `/jobs`, `/runs` и run-level UX
- live progress, ETA и progress bar для активных app-managed задач
- runtime state активного run в памяти и в `var/runtime/`
- перевод незавершенных `running`-запусков в `interrupted` после рестарта приложения
- удаление задач из UI и API с защитой от удаления активного job
- list-first UX для `/profiles` и `/jobs`: основной список и раскрывающаяся форма сверху
- единый icon-button action UX с `title` / tooltip и скрытым текстом для доступности
- логотип в шапке на базе favicon
- встроенный экран `/ops` с базовым operational runbook
- базовая чистка адаптивной верстки и cleanup тестового harness без `ResourceWarning`

## Отдельно вне MVP

- двусторонняя синхронизация
- delete propagation
- conflict resolution
- multi-user auth
- production-grade deployment за пределами локального Mac
