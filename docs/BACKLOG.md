# Backlog

## P0

### 1. Dry-run и предпросмотр перед первым запуском

Почему важно:
- сейчас перед первым большим переносом не хватает безопасного preview
- это особенно важно для длинных облачных выгрузок и нестабильных по скорости каталогов

Что должно быть:
- `rclone copy --dry-run`
- summary по количеству файлов и байт
- отдельный экран подтверждения

### 2. Recovery flow для `interrupted` задач

Почему важно:
- приложение уже умеет переводить незавершенные run в `interrupted`
- но пользователю все еще нужен более явный сценарий “что делать дальше”

Что должно быть:
- заметный recovery CTA в `/runs` и `/runs/{id}`
- явная подсказка, что повторный `copy` пойдет по дельте
- отдельное описание последнего известного прогресса

### 3. Решение по re-attach к живому `rclone` процессу

Почему важно:
- текущий restart-safe режим фиксирует прерывание, но не продолжает уже живой процесс
- это архитектурное решение с заметным риском и complexity cost

Что должно быть:
- явное решение: поддерживаем re-attach или оставляем recovery через повторный `copy`
- если поддерживаем: протокол идентификации процесса и безопасный attach
- если не поддерживаем: зафиксированное продуктовое ограничение в docs и UI

## P1

### 4. Улучшенная диагностика профилей

Почему важно:
- статус `недоступен` полезен, но нужен richer контекст

Что должно быть:
- сохранение последней ошибки проверки
- кнопка “Проверить еще раз”
- отдельные hints для `S3`, `Yandex`, локальных папок

### 5. Явная документация и UX про локальный путь трафика

Почему важно:
- пользователю легко предположить, что `S3 -> Яндекс Диск` идет напрямую между облаками
- это влияет на ожидания по скорости, стабильности и поведению при sleep/reboot

Что должно быть:
- заметный текст в UI при создании и запуске cloud-to-cloud задач
- короткий runbook в документации
- hints про влияние локального интернета, sleep и перезапуска `Mac`

### 6. Конфигурирование `rclone remote` через UI

Почему важно:
- сейчас cloud setup разбит между UI и терминалом

Что должно быть:
- guided setup для `S3`
- guided OAuth flow для `Yandex Disk`
- безопасная работа с секретами и Keychain

## P2

### 7. Backup/restore конфигурации приложения

Почему важно:
- упростит перенос на другой Mac

Что должно быть:
- экспорт профилей и job без секретов
- импорт с валидацией

### 8. Нотификации о завершении и ошибках

Почему важно:
- long-running sync лучше не отслеживать вручную

Что должно быть:
- macOS notification
- опционально Telegram/email

### 9. Более богатая операционная документация

Почему важно:
- проект уже перешел из “прототипа” в “рабочий локальный инструмент”

Что должно быть:
- runbook по типовым ошибкам
- onboarding для новых remotes
- раздел recovery/rollback
- инструкция, как безопасно возобновлять перенос после перезагрузки `Mac`

## Уже сделано

- live progress, ETA и progress bar для активных app-managed задач
- runtime state активного run в памяти и в `var/runtime/`
- перевод незавершенных `running`-запусков в `interrupted` после рестарта приложения
- удаление задач из UI и API с защитой от удаления активного job
- recovery UX первого уровня в `/runs` и `/runs/{id}`
- базовая правка верстки таблиц и favicon

## Отдельно вне MVP

- двусторонняя синхронизация
- delete propagation
- conflict resolution
- multi-user auth
- production-grade deployment за пределами локального Mac
