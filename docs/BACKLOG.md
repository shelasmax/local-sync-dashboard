# Backlog

## P0

### 1. Усилить recovery UX для repeat-from-delta

Почему важно:
- продуктовое решение уже принято: `re-attach` не поддерживается
- значит пользовательский сценарий восстановления должен быть максимально ясным и спокойным

Что должно быть:
- явный текст, что восстановление идет через повторный `copy` с дельты
- заметный pre-run checklist для длинных cloud job
- run-level подсказки, когда лучше запускать ночью и не давать Mac уйти в sleep

## P1

### 2. Улучшенная диагностика профилей

Почему важно:
- статус `недоступен` полезен, но нужен richer контекст

Что должно быть:
- сохранение последней ошибки проверки
- кнопка “Проверить еще раз”
- отдельные hints для `S3`, `Yandex`, локальных папок

Что уже частично есть:
- ручная кнопка перепроверки профиля
- базовые hints для локальных путей и отсутствующих `rclone remote`
- сохранение последнего результата проверки в локальном состоянии и показ его в UI
- разные диагностические hints для `S3`, `Yandex` и local path
- action-oriented CTA: `Открыть setup`, `Исправить профиль`, `Проверить после исправления`

### 3. Явная документация и UX про локальный путь трафика

Почему важно:
- пользователю легко предположить, что `S3 -> Яндекс Диск` идет напрямую между облаками
- это влияет на ожидания по скорости, стабильности и поведению при sleep/reboot

Что должно быть:
- заметный текст в UI при создании и запуске cloud-to-cloud задач
- короткий runbook в документации
- hints про влияние локального интернета, sleep и перезапуска `Mac`

Что уже частично есть:
- предупреждения в `/setup`
- предупреждения при составлении маршрута и в списке задач на `/jobs`

### 4. Конфигурирование `rclone remote` через UI

Почему важно:
- сейчас cloud setup разбит между UI и терминалом

Что должно быть:
- guided setup для `S3`
- guided OAuth flow для `Yandex Disk`
- безопасная работа с секретами и Keychain

## P2

### 5. Backup/restore конфигурации приложения

Почему важно:
- упростит перенос на другой Mac

Что должно быть:
- экспорт профилей и job без секретов
- импорт с валидацией

### 6. Нотификации о завершении и ошибках

Почему важно:
- long-running sync лучше не отслеживать вручную

Что должно быть:
- macOS notification
- опционально Telegram/email

### 7. Более богатая операционная документация

Почему важно:
- проект уже перешел из “прототипа” в “рабочий локальный инструмент”

Что должно быть:
- runbook по типовым ошибкам
- onboarding для новых remotes
- раздел recovery/rollback
- инструкция, как безопасно возобновлять перенос после перезагрузки `Mac`

## Уже сделано

- принято продуктовое решение: `re-attach` к живому `rclone` процессу не поддерживается
- `dry-run preview` для сохраненной задачи перед реальным запуском
- recovery flow для `interrupted` задач с повтором по дельте из `/runs`, `/jobs` и главной
- live progress, ETA и progress bar для активных app-managed задач
- runtime state активного run в памяти и в `var/runtime/`
- перевод незавершенных `running`-запусков в `interrupted` после рестарта приложения
- удаление задач из UI и API с защитой от удаления активного job
- базовая правка верстки таблиц и favicon
- cleanup тестового harness: SQLite engine закрывается корректно, без `ResourceWarning`

## Отдельно вне MVP

- двусторонняя синхронизация
- delete propagation
- conflict resolution
- multi-user auth
- production-grade deployment за пределами локального Mac
