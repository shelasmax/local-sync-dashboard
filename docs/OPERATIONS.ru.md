# Эксплуатация на macOS

[English](OPERATIONS.md) · **Русский** · [К проекту](../README.ru.md)

## Ручной запуск и постоянная работа

Минимальный вариант — терминал с `uvicorn app.main:app --host 127.0.0.1 --port 8000`. Оставьте его открытым на время работы задач. Для реальных переносов не используйте `--reload`.

Для постоянной эксплуатации есть пользовательский LaunchAgent macOS. Он запускает **service-копию вне `~/Documents`**:

```text
~/Library/Application Support/com.localsync.dashboard/service
```

Так фоновый запуск не зависит от доступа к репозиторию в папке, защищённой настройками приватности macOS. Сервис работает в пользовательской сессии, а Mac должен оставаться включённым и подключённым к сети.

## Установка или обновление service-копии

Сначала выполните [ручную установку](../README.ru.md#быстрый-старт) и проверьте небольшой dry-run. Для создания виртуального окружения скрипт использует `/usr/bin/python3`; проверьте, что его версия соответствует требованию **Python 3.11+**. Иначе заранее создайте service-окружение подходящим Python:

```bash
python3 --version  # Нужна версия 3.11 или новее
mkdir -p "$HOME/Library/Application Support/com.localsync.dashboard/service"
python3 -m venv "$HOME/Library/Application Support/com.localsync.dashboard/service/.venv"
```

Дождитесь завершения активных задач и остановите вручную запущенное приложение, чтобы освободить порт 8000. Из корня репозитория:

```bash
./scripts/update_launchd_service.sh
./scripts/launchd_status.sh
```

Скрипт копирует код в service-каталог, обновляет виртуальное окружение, записывает plist и перезапускает `com.localsync.dashboard`. Его `rsync --delete` удаляет устаревшие **файлы кода service-копии**, исключая `var/` и `.venv/`. Данные в хранилищах источника и назначения он не переносит и не удаляет.

**Первая установка:** `var/` репозитория исключён из копирования. Существующие профили, задачи и история автоматически не переносятся. Если они нужны, остановите оба экземпляра приложения и восстановите приватную резервную копию в `var/` сервиса до использования расписаний.

**Проверка:** запустите скрипт статуса, откройте [127.0.0.1:8000](http://127.0.0.1:8000), проверьте профили и маршруты, выполните небольшой dry-run. В `/ops` есть сценарии для remotes, монтирования, авторизации, прерванных запусков и лимита времени.

## Резервное копирование состояния

Экспорт и импорт конфигурации без секретов запланированы; встроенного мастера миграции пока нет.

1. Дождитесь завершения копирований и остановите приложение. Для service-mode сначала выгрузите агент: простое завершение процесса может привести к его перезапуску из-за `KeepAlive`.
2. Скопируйте **весь каталог данных** в приватное место. По умолчанию это `var/` активной копии приложения; переменная `LOCAL_SYNC_DATA_DIR` может задавать другой путь. Сохраняйте предыдущую резервную копию до проверки новой.
3. Отдельно перенесите или заново настройте rclone и macOS Keychain. Копия БД не включает эти реквизиты доступа. На другом Mac при необходимости заново авторизуйте remotes и введите секреты приложения.
4. Восстанавливайте данные при остановленном приложении, проверьте пути и смонтированные тома, затем запустите соответствующую версию. Проверьте включённые расписания до возобновления фоновой работы.

Выгрузить агент:

```bash
launchctl bootout "gui/$(id -u)/com.localsync.dashboard"
```

Загрузить уже установленный plist:

```bash
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/com.localsync.dashboard.plist"
```

В резервных копиях и логах могут быть личные имена и пути. Не прикладывайте их к публичным issue без обезличивания.

## Откат и восстановление

Перед обновлением сохраните текущую ревизию кода и копию `var/`, сделанную при остановленном приложении. Для отката восстановите нужную ревизию в отдельном checkout и запустите её скрипт обновления сервиса после завершения копирований. Если совместимость схемы не подтверждена, при остановленном приложении восстановите БД из соответствующей резервной копии: additive-миграции не гарантируют совместимость со всеми старыми версиями.

Прерванный запуск получает статус `interrupted`, а последний доступный прогресс сохраняется. Проверьте тома, remotes, свободное место и настройки сна, затем повторите `rclone copy` по тому же маршруту с дельты. Не запускайте повтор, пока независимый процесс копирования продолжает писать в то же назначение.

## Настройки переноса

В задаче доступны `transfers`, `checkers`, `fast-list`, лимит скорости, фильтры и проверка checksums. Начните со значений по умолчанию, затем подберите настройки на небольшой типичной задаче. Больше параллельных операций не всегда означает выше скорость; `fast-list` требует больше памяти и зависит от поддержки backend.

Лимит одного запуска по умолчанию — 6 часов. `/ops` принимает 1–72 часа; настройка применяется к последующим запускам. Даже если оба хранилища облачные, трафик проходит через Mac.
